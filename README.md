# Paul's Python Course

<p align="center"><img src="docs/readme/cast.gif" width="100%" alt="The six of us as animated pixel art: Paul writing on a chalkboard, Neil launching a rocket, Aaesha passing a test, Caitlin shrugging and laughing, Riya with a paint palette and Yahya clicking a stopwatch."></p>

I teach Python to my friends, and this is the website for it. Neil helps me out from time to time. Everyone in it is real: the six people in that picture are us.

**[Play it here](https://bouwles.github.io/pauls-python-course/).** There's nothing to sign up for: pick who you are and start.

In the game, I've turned an old clocktower into a code school. You start on the ground floor, printing a sign for the door. Nine floors and 116 projects later you've written a neural network from scratch and a tiny GPT, trained a crab to race, and you're up on the roof building something of your own. All of it takes about 410 hours.

## How a project goes

Every project starts with one of us needing something. Caitlin has picked the restaurant for class dinner, there are six of us and one bill, and last time it took twenty minutes to settle who had the extra garlic bread. So you build a bill splitter.

![Caitlin in the Studio asking for a bill splitter, with Paul in the foreground.](docs/readme/brief.png)

You pick up the ideas a step at a time: a short explanation, an example you can run and change, and questions that ask what some code will print before you get to run it.

![A lesson on print() beside the code editor, with the program's output underneath.](docs/readme/lesson.png)

Then somebody's code turns up with a mistake in it. Yahya's tip program says a bill of 20 with a 10 per cent tip comes to 20.10. You find the bug and fix it, and I'd like a word about the variable called `c`.

![Fixing Yahya's program: the output says 20.10 where it should say 22.00, and Paul complains about the variable name.](docs/readme/fix.png)

After that you write the program yourself and tests check it. If you get stuck there are hints that give away a little more each time, and a rubber duck you can explain the problem to. The duck won't answer.

When the checks pass you ship it, and it goes on your Shelf. You can download everything there as one repository, push it to GitHub, or send a friend a link that runs it in their browser.

![The Shelf, with an example run of each program someone has shipped.](docs/readme/shelf.png)

Python runs right there in the browser, so you don't have to install anything to get going. Some later projects need more than a browser can do, like PyTorch and Pygame. You build those on your own computer and paste the test results back in.

## Around the projects

**Morning Rounds** brings each idea back a day or two after you first use it, then less often as it sticks.

**Drills** are five quick tasks against the clock. Yahya has set the time to beat on every one.

![The Drills page, with Yahya's time on each card.](docs/readme/drills.png)

**The Arcade League** is a race every week for the crabs you train in Act 8. Your crab races on the same seeds as everyone else's, and the lowest average number of moves wins. The rest of us are on the table too, so there's always someone to beat.

![A replay of a crab's race on a grid, above a table with the six of us ranked by average moves.](docs/readme/league.png)

**Certificates** are for finishing an Act, with my name on them. You can save yours as a picture or print it on a sheet of A4.

## Classes

This part is for when I'm teaching. I make a class, choose which projects to set and send everyone a join link. When they've had a go, they send me a progress link, and opening it adds them to my register with their code to read. Neil gets a co-teacher link with the same class on it, and I can share the League table the same way.

![The class page: a register of four students, showing which of the three set projects each has shipped.](docs/readme/class.png)

## A couple of other things

You don't need an account for any of this. Your progress stays in your browser, and to carry on somewhere else you take a save with you, as a file or a line of text. A class lives entirely in its link.

All the art is drawn in code. Everyone is put together pixel by pixel from a description of how they look, with 135 gestures to choose from, and every room in the tower is built the same way.
